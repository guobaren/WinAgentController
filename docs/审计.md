## Known Issues / 风险

- `scripts/RemoteController.Agent.config.json:8` 与 `scripts/Setup-RemoteControllerAgent.ps1:148` 现默认 `RegenerateIdentity=false`；只有显式改为 `true` 才会解除旧配对并轮换 TLS 身份。
- `global.json:3` 固定 SDK 8.0.422，但本机仅安装 10.0.301；本轮完整发布、AST 和 253/253 测试使用仓库外 SDK 10.0.301 workaround，仍需在固定 SDK 下复跑。
- `scripts/Setup-RemoteControllerAgent.ps1:216` 在身份重建路径发出警告，但操作者仍需在执行前确认是否允许破坏现有配对。
- `scripts/Test-RemoteControllerUi.ps1:214` 至 `:219` 依赖活动桌面上的真实滚轮反馈；锁屏、输入焦点变化或旧测试程序都会导致与本机结果不同，必须逐项核对实际状态。
- 当前跨机器目标安装的是旧版测试程序；在完整包哈希一致前，既有 4 项通过/第 5 项失败只能证明旧包链路状态，不能评价 `dd46be0` 的完整 UI 结果。
- 本次 TLS 身份变化已由用户明确发起重新配对并成功完成；旧固定连接失败记录保留为历史安全边界，后续常规刷新仍不得自动信任再次变化的身份。
- `src/Rc.Agent/Jobs/ManagedTaskRegistry.cs:412`、`:526`：目标测试任务启动失败，TaskHost 未在 10 秒内打开控制管道；尚未核对目标安装版本、TaskHost 进程和管道权限。
- 本轮已重建完整发布包，但尚未刷新目标的 Agent/TaskHost；控制端与目标组件版本一致性仍需用完整包刷新后复验。
- `src/Rc.Cli/Commands/TargetCommand.cs:14`、`:25-31`：当前目标档案命令面仅为 `add/list/use/refresh`；删除、编辑和重命名能力未实现。
- `src/Rc.Cli/Commands/TargetCommand.cs:78-83`：`target add` 在写入控制端档案前执行固定指纹 TLS probe 并读取设备 ID；该命令不建立控制端配对关系。
- `src/Rc.Cli/Commands/PairCommand.cs:13-110` 未调用 `ControllerTargetStore`；当前重新配对 `.50` 后，正式 `target list` 实测仍只有 `.47`，确认 pair/连接不会自动 add。
- `src/Rc.Cli/Program.cs:5-7`：`--text` 决定直接文本输出或捕获后生成 JSON envelope；该选项不参与目标解析和认证授权。
- `src/Rc.Agent/Program.cs:51-56` 与 `scripts/Setup-RemoteControllerAgent.ps1:216`：TLS 指纹来自持久 Agent 证书；身份修复或 `RegenerateIdentity=true` 会删除旧身份并生成新证书，同一物理机器的指纹因此可以变化。
- `scripts/Update-RemoteController.ps1:26-31`、`:72-79`：标准更新把同一 DataRoot 传给安装器，只备份/替换 InstallPath，不删除 Agent 身份；正常更新不应改变 TLS 指纹。
- `src/Rc.Cli/Commands/TargetCommand.cs:150`：`refresh` 在发现前调用防火墙规则启用逻辑；普通终端实际失败，管理员 PowerShell 实际通过，首次启用规则时必须按管理员权限运行。
- 隔离测试在系统临时目录留下一个仅含测试 `targets.json` 的目录；递归清理被执行安全策略拒绝，正式控制端档案未受影响。
- 更新脚本完成只说明更新任务结束，不自动证明 Agent/Broker/UI Agent 健康；更新后仍需 probe、认证命令和 UI 状态复核。
